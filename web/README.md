# KyanOS in the browser

The KyanOS desktop — the real Clarity compositor, window manager, and apps —
compiled from Clarity to JavaScript and running live on an HTML `<canvas>`.
No server-side rendering, no video: `compose()` paints into a byte buffer each
frame and the page blits it to the canvas; DOM mouse events flow straight into
the same `handle_mouse` path the native build uses.

**Live:** https://monkdim.github.io/Kyanos/os/

## How it works

- `runtime_browser.js` — a browser derivative of `native/runtime.js`. The Node/
  Bun host facilities (readline, `process`, `fs`, `bun:ffi`) are stubbed, and the
  five framebuffer FFI ops (`_ffi_alloc`, `_ffi_alloc_cstring`, `_ffi_fill_u32`,
  `_ffi_blend_u32`, `_ffi_copy`) are reimplemented on `Uint8Array`. Everything
  else — all 150 builtins — is preserved verbatim.
- `build/entry.js` — the browser API surface: `createDesktop`, `composeToBytes`,
  `sendMouse`, `openApp`, `toggleLauncher`, `MouseEvent`.
- `index.html` — canvas + a `requestAnimationFrame` present loop that converts
  the framebuffer's `0xAARRGGBB` (memory order B,G,R,A) to canvas RGBA, plus
  mouse routing (canvas px → desktop px).
- `kyanos.bundle.js` — the bundled result served by Pages.

## Build

```bash
python3 native/transpile.py --bundle   # transpile stdlib (incl. the Kyan modules) → native/dist
bash web/build_web.sh                   # assemble build/ + bundle → web/kyanos.bundle.js
```

`build/` is regenerated by `build_web.sh` (only `entry.js` is a source file there);
the transpiled module copies are gitignored.

## Run locally

ES-module imports are blocked over `file://`, so serve the folder:

```bash
cd web && python3 -m http.server 8000
# open http://localhost:8000/
```

## Verify (headless)

```bash
/opt/node22/bin/node web/verify.cjs   # Playwright: asserts non-blank render + a dock click opens an app
```

## Known caveats

- The transpiler emits a colliding `export`/`import` for Clarity `fn max`;
  `build_web.sh` drops the colliding import in the build artifacts (the local
  definition shadows it). A proper fix belongs in the transpiler.
- Deep in-app interactions beyond open/drag/launcher aren't exercised yet.
